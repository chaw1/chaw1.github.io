Datakeel.工程与实测Under load

我把数据集交付前的质量检查、泄漏核验和人工签批放进同一个工作台。这些实测记录了 Agent 能替人做到哪一步，也展示了并发标注时最先卡在哪里。I built Datakeel to bring quality checks, leakage review and human sign-off into one dataset workbench. These notes trace what an agent can do on its own and where the system slows down under load.

B1–B7 · 2026-11-11

两套数据库能处理多大负载？How far did each database scale?

同一台工作站上，分别用 SQLite 和 PostgreSQL 跑导入、流水线、问数和故障恢复。B2 在 8 个进程下每秒处理数千份文件。换成 B5 的 50 个交互用户，两套库都错过了 1 秒的 p95 目标。p95 表示 95% 的请求能在该时长内完成。On the same workstation, eight workers processed thousands of files per second in B2. When the workload switched to 50 interactive users in B5, both databases missed the one-second p95 target. A p95 of one second means 95% of requests finish within a second.

缩短写锁时间后，保存快了多少？What changed when the write lock got shorter?

50 位模拟标注员反复领取、保存、提交任务。原先每次领取都要在写锁内把候选任务取出，用 Python 排序。把显示顺序存入数据库后，SQLite 的整场保存 p95 从 2,841 ms 降到 188 ms，约为原来的十五分之一。Fifty simulated annotators repeatedly claimed, saved and submitted tasks. Each claim used to fetch and sort all eligible tasks in Python while holding the write lock. Persisting their display order reduced SQLite’s whole-run save p95 from 2,841 ms to 188 ms, about a fifteenfold reduction.

PyO3 · 2026-10-27

近重复哈希，速度和召回如何取舍？How fast can the hash kernel find near-duplicates?

prefix 只比较前 4 位相同的哈希，容易漏掉跨桶的样本对。exact 先用多个分段找候选，再核对完整汉明距离。10 万哈希时，Rust 的 exact 用了 0.074 秒，并找全了植入的近重复对。Prefix matching only compares hashes in the same four-bit bucket and can miss pairs across buckets. Exact matching indexes multiple segments, then verifies Hamming distance. On 100,000 hashes the Rust exact kernel took 0.074 seconds and found every planted pair.
